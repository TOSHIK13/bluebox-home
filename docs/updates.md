# Обновления Home через GitHub Releases

Статус: проект, ничего не реализовано. Дата: 2026-11-08.

## Как это будет выглядеть для владельца

1. Выпуск: `scripts/release.ps1 -Bump patch` (verify → тег `v0.2.1` → push). Дальше всё делает CI.
2. CI собирает подписанный APK и публикует Release: `bluebox-home-0.2.1.apk`, `bluebox-home-0.2.1.apk.sha256`, текст изменений в описании.
3. На ТВ: Home раз в сутки (и по кнопке) спрашивает GitHub о последнем релизе. Новее — в «Настройки → Обновления» появляется «Доступна 0.2.1», на иконке настроек в доке точка.
4. «Установить»: скачивание, проверка, системный диалог установки (подтверждается пультом). После установки Home перезапускается сам.

## Блокеры, которые надо решить до кода

- **Репозиторий `TOSHIK13/bluebox-home` приватный.** ТВ скачает релиз без токена только из публичного. Токен в приложение класть нельзя (AGENTS.md). Варианты: (а) сделать репозиторий публичным (в нём нет секретов — по правилам проекта они только в `local.properties`/env); (б) отдельный публичный репозиторий только для релизов (`bluebox-home-releases`), CI публикует туда с токеном из секрета Actions; (в) свой хостинг. Рекомендация: (б), если исходники остаются закрытыми, иначе (а).
- **Ключ подписи.** Сейчас `beta` (она стоит на ТВ) подписана `debug.keystore` этого ПК. Обновление ставится только поверх APK с тем же ключом. Нужен отдельный release-keystore (хранить вне репозитория, копия в надёжном месте, в CI — секреты `KEYSTORE_B64`, `KEY_ALIAS`, `KEY_PASSWORD`, `STORE_PASSWORD`). Переход на новый ключ = один раз удалить и поставить заново (настройки Home сбросятся). Дешёвая альтернатива: загрузить в CI существующий `debug.keystore` — без потери настроек, но слабый ключ.
- **Версии.** Сейчас `versionCode = 1`, `versionName = "0.1.0"` жёстко. Нужно брать из тега: `-PversionName=0.2.1 -PversionCode=<major*10000+minor*100+patch>`; строго возрастает, понижать нельзя (откат = новый релиз с большим номером).
- **Какой applicationId обновляем.** Релиз и `beta` — разные id (`app.bluebox.home`, `app.bluebox.home.beta`), поэтому обновляется только свой id. Решить, что ставим на ТВ постоянно (предлагаю один `release` без суффикса; debug остаётся `.debug` для разработки и не пересекается).
- **Android на приставке** (Realtek RTD1325): от версии зависит, можно ли обновлять без диалога (Android 12+ `USER_ACTION_NOT_REQUIRED` для того же установщика). Узнать `ro.build.version.sdk` на ТВ; по умолчанию считаем, что диалог будет всегда.

## Компоненты

**CI** (`.github/workflows/release.yml`, триггер — тег `v*`): checkout, JDK, `scripts/verify.ps1`-эквивалент (`gradlew test lint`), `assembleRelease` с подписью из секретов, sha256, `gh release create`. Тег с суффиксом (`v0.3.0-beta.1`) → pre-release (канал «бета»).

**Приложение** (всё без зависимостей, как остальной код):
- `logic/UpdateRules.kt` — чистая логика + JVM-тесты: разбор версии, `isNewer`, выбор нужного asset, троттлинг проверки.
- `data/UpdateSource.kt` — `GET https://api.github.com/repos/<owner>/<repo>/releases/latest` (для беты — список и первый pre-release), без токена (лимит 60 запросов/час — хватает), `org.json`, таймауты 5/8 с; ошибка сети никогда не ломает Home.
- `data/UpdateInstaller.kt` — скачивание в `cacheDir/updates` (редирект на objects.githubusercontent.com HttpURLConnection проходит), проверка размера и SHA-256, `getPackageArchiveInfo`: тот же пакет, `versionCode` больше, подпись совпадает; установка через `PackageInstaller` (сессия → `commit` → приёмник статуса; `STATUS_PENDING_USER_ACTION` → запустить системное подтверждение).
- `UpdatesActivity` (или секция в настройках): текущая версия, последняя, дата, «Проверить», «Установить», текст изменений (первые ~600 символов), канал (стабильный/бета), «Проверять автоматически» вкл/выкл.
- Манифест: `REQUEST_INSTALL_PACKAGES`. Пользователь один раз включает «Установка неизвестных приложений» для Home (кнопка ведёт в `ACTION_MANAGE_UNKNOWN_APP_SOURCES`; на ТВ экран может отсутствовать — проверить на реальном устройстве).
- Автопроверка: при старте Home не чаще раза в 24 ч, в фоне, тихо; результат пишется в `Prefs`.

**Скрипты**: `scripts/release.ps1` (проверки чистоты ветки, verify, расчёт версии, тег, push), правка `app/build.gradle.kts` (версии из свойств, `signingConfigs.release` из env/`local.properties`).

## Безопасность

- Только HTTPS и зашитые в код `owner/repo`; ссылку на скачивание берём только из ответа этого API.
- SHA-256 из релиза защищает от порчи при загрузке; от подмены реально защищает подпись: Android не поставит APK с чужим ключом. Всё равно проверяем подпись до вызова установщика, чтобы не показывать пользователю бесполезный диалог.
- Автоматической установки без подтверждения нет (кроме разрешённого системой Android 12+ сценария, и то только как опция).
- Журнал: версия, результат, ошибка — в `Log` и в строке диагностики настроек.

## Порядок работ

1. Решения по блокерам (репозиторий, ключ, id, Android ТВ) — владелец.
2. Gradle: версии из свойств, release-подпись; `release.ps1`; workflow; пробный релиз `v0.2.0-beta.1` и ручная установка на эмулятор.
3. `UpdateRules` + тесты; `UpdateSource`; строка «Обновления» в настройках (только проверка и показ версии).
4. `UpdateInstaller`: скачивание, проверки, установка на эмуляторе (подпись тем же ключом, затем релиз с большим versionCode).
5. Проверка на реальном ТВ (диалог, перезапуск Home, разрешение «неизвестные источники»), автопроверка раз в сутки, точка в доке.

Не делаем: откат на старую версию из приложения, фоновую установку без подтверждения, delta-обновления, сторонний магазин.
